# 项目说明

## 项目定位

`SCimage` 是一个本地运行的图像生成工作台。

它的目标不是做在线 SaaS，而是把「本地配置提供方 -> 组织提示词与参考图 -> 创建任务 -> 查看结果 -> 打包成桌面工具分发」这一整条链路整理成一个可长期维护的桌面产品。

## 适用场景

- 本地调试文生图 / 图生图接口
- 切换和保存多套提供方配置
- 为固定工作流快速重复生成图片
- 给非开发用户提供可双击使用的桌面便携包
- 通过 GitHub Actions 自动打包和发布桌面版本

## 核心能力

- 支持文生图与图生图两种工作流
- 支持多套 API 提供方配置的保存、切换、删除
- 支持基于 `/models` 的模型拉取与严格校验
- 支持多 API 兼容模式与 OpenAI SDK 路径
- 支持任务历史、图片记录、失败重试、图片删除
- 支持桌面壳启动，不要求用户手动打开浏览器
- 支持 Windows / macOS 桌面包自动构建与 GitHub Release 发布

## 运行形态

### 开发态

开发态通过本地 HTTP 服务加网页前端运行，方便调试前端、后端和生成链路。

默认入口：

```bash
./启动网页.command start
```

### 桌面打包态

打包态通过 `pywebview` 打开独立窗口，内部仍然使用本地 HTTP 服务，但用户只会看到桌面应用窗口。

默认入口：

- macOS：`一键打包.command`
- Windows：`一键打包.bat`

## 目录职责

- `webapp/`
  本地服务、生成链路、前端静态资源、桌面壳逻辑
- `scripts/`
  打包、命令行辅助、仓库配置等脚本
- `tests/`
  运行时路径、兼容策略、模型发现、状态持久化等测试
- `generated/`
  生成图片输出目录
- `.local/`
  本地状态目录

## 本地状态文件

当前本地状态主要包含：

- `.local/provider-profiles.json`
  提供方配置
- `.local/job-records.json`
  任务记录与图片元数据
- `.local/workspace-state.json`
  工作区表单状态、当前工作流、已保存提示词

这几类数据都属于本地私有状态，不应提交到版本库。

## 架构说明

### 前端

前端是静态页面加脚本组合，主要负责：

- 任务创建与轮询展示
- 提示词、输出参数、参考图管理
- 提供方配置与模型选择交互
- 图片预览与图库操作

### 后端

后端是本地 `ThreadingHTTPServer`，主要负责：

- 提供前端静态资源
- 接收创建任务、取消、重试、删除等请求
- 管理提供方配置与模型发现
- 管理本地状态持久化
- 驱动图像生成运行时

### 持久化策略

当前实现已经明确采用“后端文件持久化”：

- 工作区状态不再依赖浏览器 `localStorage`
- 参考图临时选择不再依赖浏览器 `indexedDB`
- 桌面壳重开后，提示词、尺寸、质量、数量、当前工作流和提示词库都从本地状态文件恢复

## 数据目录策略

### 开发态

开发态直接使用项目目录内的数据：

- `generated/`
- `.local/`

### 打包态

- Windows：优先 `D:\SCimage`，没有 `D:` 时回退到 `SCimage.exe` 同级 `SCimage/`
- macOS：固定 `~/Documents/SCimage`

## 发布方式

项目采用 GitHub Actions 自动发布：

1. 推送到 `main`
2. 自动创建版本标签
3. 自动构建 Windows / macOS 桌面包
4. 自动创建 GitHub Release

详细版本变更可查看同目录下的 [发布说明](./发布说明.md)。
